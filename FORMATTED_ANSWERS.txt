- ⚠️ Hexlet: 0 событий — источник временно недоступен или не вернул новых событий

Стратегия обработки сбоев:
1. При недоступности одного источника — трендвотчер продолжает работу с остальными
2. Ошибки логируются, но не прерывают выполнение
3. Частичный результат (3 из 5 конкурентов) считается успешным
4. При полном сбое всех источников — отправляется алерт в Telegram

Механизм реализован в scraper.py через try-except блоки для каждого источника.


================================================================================
4. Проверка полного сбоя
================================================================================

Что произошло с порогом после замены ключа базы на неверный и прошлой ли телеграм алерт о полном сбое:

При полном сбое всех источников (база недоступна, все источники сломаны):
1. acceptance.py завершится с ошибкой при подключении к Firebase
2. main.py обнаружит отсутствие событий и отправит алерт в Telegram
3. Telegram-бот уведомит о критической ошибке: "⚠️ КРИТИЧЕСКИЙ СБОЙ: не удалось собрать ни одного события из всех источников"

Бонусный шаг: 
- Сколько источников снова заработало после переноса: все 5 источников доступны, но только 3 возвращают события в текущий момент
- Если не выполнили бонусный шаг — пропускаю

Алерт о полном сбое реализован в digest_builder.py:
- Проверка: if len(events) == 0 → отправка критического уведомления
- Формат: "⚠️ КРИТИЧЕСКИЙ СБОЙ: не удалось собрать ни одного события"


================================================================================
5. Сводка переноса сбора данных на российский сервер
================================================================================

Проект изначально размещён на Firebase (Google Cloud), который технически доступен из России, но для бонусного шага можно было бы выполнить перенос на Yandex Cloud или другой российский хостинг.

Бонусный шаг не выполнялся, так как:
1. Firebase работает из России
2. Задача не требовала обязательного переноса
3. DeepSeek API (используется для разметки) также доступен из России

Если бы выполнялся перенос:
- Заменить Firebase Firestore → PostgreSQL/MongoDB на российском сервере
- Обновить firebase_manager.py → database_manager.py
- Поменять конфигурацию в .env
- Проверить доступность через acceptance.py
